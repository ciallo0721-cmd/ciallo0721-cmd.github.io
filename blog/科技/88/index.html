一、引子：为什么是这篇

这是我恢复政治写作的第一篇。

从今年6月开始，我停了整整五个月的政治写作。当时的想法很简单：觉得自己还年少，文笔不成熟，观点也难免偏激，怕说错话惹上麻烦。这五个月里我一直在观望，也在重新思考——写作这件事，到底应不应该因为「怕」而停下来。

现在，我想重新开始写。就从GFW说起。

二、GFW 到底是什么

GFW，全称 Great Firewall，中文一般叫「防火长城」，也称金盾工程、防火墙，或者干脆简称「墙」。它于1998年被正式提出，2000年之后进入全面建设阶段。

简单来说，GFW 可以理解为在中国大陆境内对互联网进行过滤、监控和限制的技术系统。

很多人以为它是一堵「墙」——一块固定不动的挡板，把墙外的东西死死挡住。其实这是误读。它更像一套动态运转的系统，不是静态的屏障，而是持续在判断、在调整、在升级的过滤网络。它的工作方式包括：

  • DNS 污染或劫持：让你在解析域名时拿到一个假地址，根本连不上真实服务器
  • 封 IP：直接把目标服务器的地址拉黑
  • SNI 检测和封锁：在握手阶段就识别你要访问的域名，说「不」
  • 以及更多不公开记录在案的手段……

被墙的网站名单很长：Facebook、X（原 Twitter）、Instagram、Google 系列（除了 google.cn 和 Chrome）、BBC、Telegram、《纽约时报》《华尔街日报》、YouTube、Netflix、Blogger、WordPress、WhatsApp、彭博新闻社、维基百科、Flickr、TikTok 国际版……这份名单从新闻媒体、社交平台一直排到开发者工具，几乎覆盖了整个「墙外互联网」的主流服务。连 GitHub 也被特殊照顾——少数仓库和 IP 时好时坏。

它的演变大致可以分三个阶段：

2002–2008年，初期阶段。 这一年起 Google 首次被间接封锁——和今天的 GitHub 一样，时好时坏，时灵时不灵。

2009–2014年，中期阶段。 Facebook、Twitter、YouTube 等相继被封锁，DPI（深度包检测）技术被引入。墙开始不只看「你去哪」，还开始看「你传输了什么」。

2015年至今，后期阶段。 Google、Instagram 等被彻底封锁。2015年，有研究表明墙可以反向发起 DDoS 攻击——这标志着 GFW 从被动过滤进化到了「主动干预」。

一句话概括它的本质：墙不是死的，它在学习。

还有一点经常被忽略：墙并不只是国家在参与。过滤和限制存在于整条链路的每一环——你家的电脑上，有软件层面的安全管控和家长控制；你家路由器内部，有运营商推送的默认 DNS 和各种过滤设置；再往外，是运营商的骨干网过滤、城市层面的封锁、某些省份的专用墙，最后才轮到国家的墙。层层叠叠，每一层都在做「过滤」这件事。

所以我们平时说的「翻墙」，翻的往往只是最外面那一层。而真正塑造了体验的，是这一整条从你网线插口开始就层层设卡的链路——墙不只是一个位于国境线上的系统，它是一套从你家里就开始的、层层嵌套的结构。

墙的触角甚至伸到了不属于你的设备上。据维基百科的记载，国外 SIM 卡漫游到中国境内时会采取另一套封锁策略：有用户实测，境外卡漫游时访问部分政治和新闻网站会被屏蔽——无痕模式下 HTTP 访问会被跳转到反诈页面，HTTPS 访问论坛则直接触发 RST 断连，启用加密 DNS 工具后才恢复正常；更有疑似运营商侧的旁路设备在「抢答」DNS 请求，相当于把对内卡的管理规则直接套到了外卡头上。连一张外国 SIM 卡进了国门都要被重新「安排」，这套系统的覆盖思路可见一斑。这个例子也说明了上面「层层都是墙」的判断：这里起作用的不是国家级的 GFW 本体，而是运营商自己的墙机制——漫游场景下没有 GFW 接管，封锁照样发生，说明运营商侧的过滤设备就是这套体系里独立运作的一层。

三、我和墙的日常

是的，如标题所见，我也被墙困扰过。

作为一个开发者，我对墙最直观的感受不在宏大叙事里，而在 everyday 的细节里：查文档时突然断连，页面转了半天加载出个「连接已重置」；GitHub 时通时断，运气不好的一天里 push 全部失败；克隆仓库要先配好代理，否则速度以「字节每秒」计；查资料得先想想有没有镜像站，没有的话就得绕路。

一来二去，我感觉自己查个资料像做贼一样。

这种感受很难向外人解释。他们觉得「上不了 Facebook 关你什么事」，但对一个依赖开源社区和英文文档的编程学习者来说，墙不是遥远的政治符号，是每天都要绕一次的坑。

顺便讲讲 VPN 和 Clash 这类工具的原理，毕竟它们就是「做贼」时戴的手套。思路说穿了很简单：隐藏你真正想访问的点。你先把加密流量发给一台架在墙外的 VPN 服务器，由它替你去访问目标网站，把资源下载下来，再原样塞回你的设备。在运营商和墙看来，你的设备从头到尾只跟那台 VPN 服务器通信——它们看见的是 VPN 服务器的 IP，而不是你要去的 Google 或 GitHub。

但这是有利有弊的。利很直接：能访问了。弊藏在你和 VPN 之间：所有流量都经过提供商的手，它技术上完全有能力监视你的访问记录，甚至出卖你的信息。你躲开了墙的视线，却把自己交给了一个几乎不受监管的第三方——这不是没有监视，只是换了个监视的人。

四、官方的理由，与我的回应

我得承认，GFW 的存在有其逻辑：维护国家安全、抵御境外有害信息、防止网络攻击、保护社会稳定。这些理由我不打算全盘否定——任何国家的网络治理都需要一套规则，这一点上我不装清高。

但理由正当，不等于执行无可挑剔。同一个理由之下，可以有完全不同的执行方式，而问题恰恰出在执行上。

五、我的态度（不是非黑即白）

我对GFW的态度是复杂的：我当然支持它的存在，但也反对其中一些做法。

GFW 的存在是有其合理性的。它可以在一定程度上保护国家安全和社会稳定，防止有害信息的传播——这就像小区需要门禁，我不反对门禁本身。

然而，我反对的是它误封合法网站。比如 GitHub、Hugging Face 这类平台——GitHub 是全球开发者的协作基础设施，Hugging Face 是开源 AI 模型的集散地，这些网站对科技创新和学术研究有着实实在在的重要作用。封掉它们，墙没能挡住什么「有害信息」，反而实实在在拖慢了墙内的人。

所以我不是在喊口号。我想要的不是「没有规则」的互联网，而是规则的正当程序：一个网站为什么被封、依据什么标准、申诉了找谁、多久能给答复——这些应该有说法。审查与治理不是一回事，治理是可预期的规则，审查是不解释的黑箱。现在的墙，更像后者。

六、结语

回到开头那个问题：我对GFW的看法，一句话说就是「支持存在，反对滥用」。

它既有其合理性，也有其问题。我希望未来的 GFW 能够更加透明和公正：封要有明确的理由和标准，误封要有通畅的申诉渠道，而不是像现在这样——一个网站悄无声息地消失，连一句解释都没有。

墙可以存在，但墙也应该讲道理。

这是我恢复政治写作的第一篇。五个月的停顿之后，我发现当初担心的「偏激进麻烦」，最终没有拦住我重新提笔。
